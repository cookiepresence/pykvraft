\section{What is Raft?}
\label{sec:orge266d73}
The project was an attempt at making a fault-tolerant key value store. To replicate the various nodes and ensure that they are consistent, we use Raft (Ongaro, Diego and Ousterhout, John, 2014), an alterantive to Multi-Paxos (Lamport, Leslie, 1998) that is touted to be simpler to understand and implement. One key difference between Multi-Paxos and raft is the strong leader property, which enforces the logs of the leader on all of the follower nodes to ensure that all nodes are synced. This ensures that there are no updates lost on the way.

Raft is not intended for fully replacing a key-value store, rather using it as a fundamental building block on top of other services (for example: lock services, configuration, etc.). This is because all updates for Raft have to pass through the leader, which creates a bottleneck for cluster. Raft also errs towards consistency over availablilty, further impacting performance.
